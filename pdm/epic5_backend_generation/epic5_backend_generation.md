# Epic 5 — Backend generation

## Overview

Generate the actual FastAPI project **on the fastapi-skills foundation** (decision Q1). The principle is
**deterministic foundation, LLM for the domain parts**:

1. Every project starts from the `feat/fastapi` template at the pinned commit (`template.lock`) plus our
   **overlay**, which fills the template's gaps: tests, ruff, logger, rate limiting, CORS, error codes, and the
   migrate-on-start entrypoint.
2. The fastapi-skills skill is placed in the workspace (3.4). The engine adds **one feature module per entity**,
   following the skill's "Adding a New Feature Module" steps.
3. Alembic migrations are autogenerated by running `make newmg` in the sandbox, not written by the LLM.
4. Deterministic post-checks verify the result. The `conventions` check in 6.2 enforces the skill's 6 pillars.

**Requirements:** FR-03, FR-04, FR-05, FR-16 (source parts) · **Changes vs v1.0:** see the README and requirements v1.1 §6

## Generated project (fastapi-skills layout)

```
project/
├── src/
│   ├── main.py  routers.py                          # template (routers registered in lifespan)
│   ├── configs/{config.py, logger.py}               # template + overlay (logger filled, CORS_ORIGINS)
│   ├── libs/
│   │   ├── database/session.py  repository/base_repository.py  decorators/transactional_decorator.py   # template
│   │   ├── exceptions/{base_exception.py (+ConflictException), error_codes.py}                       # template + overlay
│   │   └── rate_limit/limiter.py                    # overlay (slowapi)
│   └── modules/
│       ├── __init__.py                              # engine: imports every ORM model (Alembic discovery)
│       ├── health/                                  # template
│       ├── shared/domain/entities/<entity>_entity.py           # engine: pure Pydantic
│       ├── shared/infrastructure/models/<entity>_model.py      # engine: SQLModel table=True
│       └── <entities>/                              # engine: one module per entity
│           ├── ports/output/<entity>_repository.py             # I<Entity>Repository (ABC)
│           ├── infrastructure/persistence/<entity>_repository.py   # impl + I<Entity>RepoDep
│           ├── usecases/<action>_<entity>_usecase.py           # @Transactional writes + <Action><Entity>UsecaseDep
│           └── presenter/{router.py, dtos/}                    # DTOs with to_entity(), operation_id on routes
├── alembic/versions/   alembic.ini                  # template env.py; migrations autogenerated in sandbox
├── tests/{conftest.py, modules/<entities>/test_<entity>_api.py}   # overlay conftest + engine tests
├── requirements.txt  requirements-dev.txt  pyproject.toml (ruff + pytest config only)
├── Dockerfile  docker-entrypoint.sh  docker-compose.yml  Makefile  .env.ex  README.md  CLAUDE.md
└── .bga/{spec.json, plan.json}                      # excluded from the ZIP
```
