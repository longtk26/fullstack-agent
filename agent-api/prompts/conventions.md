## Backend Generation Agent — project rules

This project is generated by the Backend Generation Agent. The `fastapi-skills` skill is the foundation:
follow its layout, its "Adding a New Feature Module" steps and its 6-pillar checklist. The rules below are
additions; when they seem to conflict with the skill, these win.

- **Specification is the contract.** `.bga/spec.json` (BackendSpec) and `.bga/plan.json` (architecture plan) are
  the source of truth. Implement exactly the planned files, classes, modules and operations: no extra endpoints,
  no renamed paths, no missing ones.
- **Stable operation ids.** Every route sets `operation_id="<operationId>"` exactly as written in the plan
  (for example `operation_id="task.create"`). Never derive or prettify it.
- **Names.** Python attributes and database columns are snake_case (`project_id`). The HTTP API keeps the spec's
  camelCase (`projectId`) for JSON bodies and query parameters: DTOs use
  `model_config = ConfigDict(alias_generator=to_camel, populate_by_name=True)`, query parameters use
  `Query(alias="projectId")`.
- **Errors.** Raise the `BaseException` subclasses from `src.libs.exceptions` (`NotFoundException`,
  `BadRequestException`, `ConflictException`, `ForbiddenException`, …) with an `ErrorCode`; the response body is
  `{"error": {"code", "message", "details"}}`. Request validation errors are already rendered as 422
  `VALIDATION_ERROR`. Never raise a raw `HTTPException` in a use case.
- **Lists** return `{items, total, limit, offset}` with `limit` (default 20, max 100) and `offset` query parameters;
  sorting is `?sort=<field>` / `?sort=-<field>` limited to the declared fields (anything else → 422).
- **No secrets in code.** Signing keys, passwords and URLs come from settings (`src/configs/config.py`) backed by
  environment variables. Add new variables to `.env.ex` without real values.
- **Owned files.** Do not edit `src/libs/**`, `src/configs/**`, `src/main.py`, `alembic/env.py`, `alembic.ini`,
  `tests/conftest.py`, `scripts/seed.py`, `docker-entrypoint.sh`, `pyproject.toml`, `requirements-dev.txt` or the
  `Makefile`; they are maintained by the generator and checked. Do not write Alembic migrations; they are
  autogenerated from the models.
- **Logging.** Use `get_logger(__name__)` from `src.configs` and log writes with context
  (`logger.info("task created", extra={"task_id": str(task.id)})`).
- **Do not guess business policy.** If the spec leaves a critical rule ambiguous (who may delete, allowed state
  changes, money calculations), implement the safe minimum and list the question in `.bga/unresolved.md`.
- **You cannot run commands.** Write code and tests only; a separate system installs dependencies, runs ruff,
  migrations and pytest, and reports failures back to you. Keep lines ≤ 120 characters and imports sorted (ruff).
