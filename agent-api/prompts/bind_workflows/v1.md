An app was drafted for the business below. A tester will check the expectations below against the running app.
Translate the business words into the app's own terms so a program can run every check. You only translate: never
change, drop or soften an expectation; when something has no counterpart in the app, list it in `unbound` (that is a
finding, not a failure of yours).

- actors: each actor id → the app role that plays it (one of the roles below), "" when none.
- records: each record word used in the expectations → the app entity, the operation id that reads ONE record by id
  (`getOperation`), the response field holding its status (`statusField`, "" when none) and, for every status word in
  the expectations, the app's value (`statuses`), and the operation that lists them (`listOperation`; used when a
  path needs a record it does not create).
- setup: calls that fetch records the paths need but do not create: `var` is the record word in snake_case, `as` the
  role that reads it, `save` the response path of its id (e.g. `items.0.id`).
- steps: for EVERY step of every path, the operation that performs it, as the step's allowed actor would:
  `pathParamsJson` / `queryJson` / `bodyJson` are JSON objects as text ("" for none), with realistic values and the
  exact field names and enum values of the operation. Variables: `{{ "{{<record word in snake_case>}}" }}` is the id of
  that record (saved when a step `creates` it, or by setup), `{{ "{{run}}" }}` a short unique text, and for every demo
  user `{{ "{{user.<role>.email}}" }}` / `{{ "{{user.<role>.id}}" }}` (a second user of a role:
  `{{ "{{user.other:<role>.email}}" }}`). When the app needs to know which person a record is for, fill it with that
  user's variables.
  `creates`: the record word when the step creates its record, else "". `page` / `pageParamsJson`: the app page where
  the actor does this step (a page id) and its route parameters.
  Choose the values so the record really takes THIS path: read the steps' rules below (e.g. when a path needs an
  amount above a threshold, the amount must be above it; when a branch is for small amounts, below).
  `automatic`: true only when the app performs this step by itself as part of the previous step; then leave the call
  empty.
- effects: for every expected effect, a call that reads the number that must change (`field`: its response path), as
  `as`; for "created", a list operation and `total`.
- outcomes: per path and per outcome actor, the page where the result should be visible.
Use only operation ids and page ids from the lists. Answer with the JSON object only.
